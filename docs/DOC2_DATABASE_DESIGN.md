## 1. Schema Overview

### 1.1 Design Principles

- **Multi-tenant isolation**: Every business table carries `organization_id`. Row Level Security (RLS) enforces tenant boundaries at the database layer, making application-level leaks structurally impossible.
- **UUID primary keys**: All tables use `uuid` primary keys generated by `gen_random_uuid()`. UUIDs are safe for distributed inserts, opaque to enumeration attacks, and compatible with Supabase client libraries.
- **Soft delete**: Tables representing business entities include `deleted_at TIMESTAMPTZ`. A non-null value means the row is logically deleted. All queries filter on `deleted_at IS NULL` via views or RLS.
- **Audit fields**: Every table includes `created_at`, `updated_at`, `created_by`, `updated_by`. Triggers maintain `updated_at` automatically.
- **Immutable cost history**: Cost and price changes are never overwritten; they are appended to history tables so any historical cost can be reconstructed.
- **Versioned recipes**: Recipes carry a version number. Editing a recipe creates a new version; the previous version is preserved for cost history, regulatory traceability, and menu archaeology.
- **Integer arithmetic for money**: All monetary values are stored as `BIGINT` in minor currency units (fils for AED, cents for USD). This eliminates floating-point rounding errors that plague restaurant costing. The column comment documents the unit (e.g., "AED fils" or "USD cents").
- **Weight in milligrams**: All weight values are stored as `BIGINT` in milligrams. This avoids decimal precision issues when converting between grams and kilograms. Display layers convert to the user's preferred unit.
- **Nutrition in micrograms or milligrams**: Stored as integers to avoid rounding drift across recipe rollups.

### 1.2 Schema Organization

```
public                 -- All application tables (Supabase default schema)
  auth                 -- Supabase managed auth (users, sessions, tokens)
  storage              -- Supabase managed file storage (product images, documents)
  extensions           -- PostgreSQL extensions
```

We use the `public` schema for all application tables. Supabase manages `auth` and `storage` schemas. We do not create custom schemas because Supabase RLS policies, realtime subscriptions, and client libraries work most reliably against `public`.

## 3. Core Foundation Tables

These tables establish the multi-tenant hierarchy and shared reference data that every other table depends on.

### 3.1 organizations

The root tenant table. Every piece of business data is scoped to an organization. A single restaurant, a hotel group, or a catering company each gets one organization row.

```sql
CREATE TABLE organizations (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  -- Identity
  name            TEXT NOT NULL,
  slug            TEXT NOT NULL UNIQUE,                -- URL-safe identifier, e.g., "anchor-hospitality"
  legal_name      TEXT,                                -- Full legal entity name for invoices/contracts
  tax_id          TEXT,                                -- VAT/TRN number (e.g., UAE TRN)

  -- Contact
  email           TEXT,
  phone           TEXT,
  website         TEXT,

  -- Address
  address_line1   TEXT,
  address_line2   TEXT,
  city            TEXT,
  state_province  TEXT,
  postal_code     TEXT,
  country_code    CHAR(2),                             -- ISO 3166-1 alpha-2

  -- Configuration
  default_currency_code CHAR(3) NOT NULL DEFAULT 'AED', -- ISO 4217
  default_timezone      TEXT NOT NULL DEFAULT 'Asia/Dubai',
  fiscal_year_start_month SMALLINT NOT NULL DEFAULT 1 CHECK (fiscal_year_start_month BETWEEN 1 AND 12),

  -- Subscription / Licensing
  plan_tier       TEXT NOT NULL DEFAULT 'trial',       -- trial, starter, professional, enterprise
  max_locations   INT NOT NULL DEFAULT 1,
  max_users       INT NOT NULL DEFAULT 5,

  -- Branding
  logo_url        TEXT,                                -- Supabase storage path

  -- Audit
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),
  updated_by      UUID REFERENCES auth.users(id),
  deleted_at      TIMESTAMPTZ                          -- Soft delete
);

-- WHY: Organizations are the tenant boundary. Every query in the system
-- filters by organization_id. The slug enables clean URLs. Currency and
-- timezone defaults cascade to child records unless overridden.

COMMENT ON TABLE organizations IS 'Root tenant entity. All business data is scoped to an organization.';
COMMENT ON COLUMN organizations.default_currency_code IS 'ISO 4217 currency code. AED for UAE-based restaurants.';
COMMENT ON COLUMN organizations.slug IS 'URL-safe unique identifier for routing and API paths.';
```

### 3.2 locations

A physical site within an organization: a restaurant, a hotel kitchen, a central production facility, a warehouse.

```sql
CREATE TABLE locations (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,

  -- Identity
  name            TEXT NOT NULL,                       -- "Downtown Branch", "Main Kitchen"
  code            TEXT,                                -- Short code for POS/ERP integration, e.g., "DT01"
  location_type   TEXT NOT NULL DEFAULT 'restaurant',  -- restaurant, kitchen, warehouse, commissary

  -- Contact
  email           TEXT,
  phone           TEXT,

  -- Address
  address_line1   TEXT,
  address_line2   TEXT,
  city            TEXT,
  state_province  TEXT,
  postal_code     TEXT,
  country_code    CHAR(2),

  -- Configuration
  currency_code   CHAR(3),                             -- Override org default if this location uses a different currency
  timezone        TEXT,                                 -- Override org default

  -- Operational
  is_active       BOOLEAN NOT NULL DEFAULT true,
  opening_date    DATE,
  closing_date    DATE,

  -- Audit
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),
  updated_by      UUID REFERENCES auth.users(id),
  deleted_at      TIMESTAMPTZ,

  -- Constraints
  UNIQUE (organization_id, code),
  UNIQUE (organization_id, name)
);

-- WHY: Locations enable per-site inventory, costing (prices vary by location),
-- and access control. A hotel group may have kitchens in different countries
-- with different currencies and suppliers. The code field supports POS integration.

COMMENT ON TABLE locations IS 'Physical sites within an organization: restaurants, kitchens, warehouses.';
```

### 3.4 currencies

Reference table for all currencies used across the organization.

```sql
CREATE TABLE currencies (
  code            CHAR(3) PRIMARY KEY,                 -- ISO 4217: AED, USD, EUR, GBP
  name            TEXT NOT NULL,                       -- "UAE Dirham"
  symbol          TEXT NOT NULL,                       -- "AED", "$", "EUR"
  minor_unit_name TEXT NOT NULL DEFAULT 'cents',       -- "fils" for AED, "cents" for USD
  decimal_places  SMALLINT NOT NULL DEFAULT 2,         -- 2 for most, 0 for JPY, 3 for BHD/KWD
  is_active       BOOLEAN NOT NULL DEFAULT true,

  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- WHY: The Excel workbook stores all costs in AED. A multi-national deployment
-- needs currency awareness. The decimal_places field tells the UI how to format.
-- AED has 2 decimal places (1 AED = 100 fils). We store values in fils (minor units).

-- Seed essential currencies
INSERT INTO currencies (code, name, symbol, minor_unit_name, decimal_places) VALUES
  ('AED', 'UAE Dirham', 'AED', 'fils', 2),
  ('USD', 'US Dollar', '$', 'cents', 2),
  ('EUR', 'Euro', 'EUR', 'cents', 2),
  ('GBP', 'British Pound', 'GBP', 'pence', 2),
  ('SAR', 'Saudi Riyal', 'SAR', 'halalas', 2);

COMMENT ON TABLE currencies IS 'ISO 4217 currency reference. All monetary values stored in minor units.';
```

### 3.5 exchange_rates

Daily exchange rates for multi-currency cost comparison.

```sql
CREATE TABLE exchange_rates (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,

  from_currency   CHAR(3) NOT NULL REFERENCES currencies(code),
  to_currency     CHAR(3) NOT NULL REFERENCES currencies(code),
  rate            NUMERIC(18, 8) NOT NULL,             -- e.g., 1 USD = 3.67250000 AED
  effective_date  DATE NOT NULL,
  source          TEXT,                                -- "manual", "api:openexchangerates", "bank"

  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),

  UNIQUE (organization_id, from_currency, to_currency, effective_date),
  CHECK (from_currency <> to_currency),
  CHECK (rate > 0)
);

-- WHY: International hotel groups purchase ingredients in local currencies but
-- report costs in a base currency. Exchange rates are per-organization because
-- large groups may negotiate different rates than the market spot rate.

COMMENT ON TABLE exchange_rates IS 'Historical exchange rates for multi-currency cost conversion.';
```

### 3.6 tax_rates

Tax rate definitions (VAT, sales tax, municipality fees).

```sql
CREATE TABLE tax_rates (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,

  name            TEXT NOT NULL,                       -- "UAE VAT", "Tourism Dirham", "Municipality Fee"
  rate_percent    NUMERIC(6, 4) NOT NULL,              -- 5.0000 for 5% UAE VAT
  is_compound     BOOLEAN NOT NULL DEFAULT false,      -- True if this tax applies on top of other taxes
  is_inclusive    BOOLEAN NOT NULL DEFAULT false,       -- True if prices already include this tax
  is_active       BOOLEAN NOT NULL DEFAULT true,
  effective_from  DATE NOT NULL DEFAULT CURRENT_DATE,
  effective_to    DATE,                                -- NULL means currently active

  -- Audit
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),
  updated_by      UUID REFERENCES auth.users(id),

  UNIQUE (organization_id, name, effective_from),
  CHECK (rate_percent >= 0 AND rate_percent <= 100)
);

-- WHY: The Excel template calculates "Total+5%" and "Price W/VAT" / "Price-VAT".
-- This table makes tax rates configurable per organization. The 5% in the Excel
-- maps to UAE VAT. Hotels may also charge tourism fees or municipality levies.

COMMENT ON TABLE tax_rates IS 'Tax rate definitions. Maps to the 5% VAT calculation in the Excel workbook.';
COMMENT ON COLUMN tax_rates.rate_percent IS 'Tax percentage. 5.0000 = 5% UAE VAT from the Excel "Total+5%" field.';
```

### 3.8 unit_conversions

Product-specific unit conversions. A "block" of butter weighs 10,000g, but a "block" of cheese weighs 2,000g.

```sql
CREATE TABLE unit_conversions (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,

  from_unit_id    UUID NOT NULL REFERENCES units_of_measure(id),
  to_unit_id      UUID NOT NULL REFERENCES units_of_measure(id),

  -- Optional product scope: if NULL, this conversion applies to all products
  -- If set, it overrides any generic conversion for this specific product
  product_id      UUID REFERENCES products(id) ON DELETE CASCADE,

  conversion_factor NUMERIC(18, 8) NOT NULL,           -- 1 from_unit = X to_units
                                                       -- e.g., 1 blk butter = 10000 g -> 10000.0

  is_bidirectional BOOLEAN NOT NULL DEFAULT true,      -- If true, reverse conversion = 1/factor

  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),
  updated_by      UUID REFERENCES auth.users(id),

  UNIQUE (organization_id, from_unit_id, to_unit_id, COALESCE(product_id, '00000000-0000-0000-0000-000000000000'::uuid)),
  CHECK (from_unit_id <> to_unit_id),
  CHECK (conversion_factor > 0)
);

-- WHY: The Excel workbook encodes product-specific conversions implicitly:
--   BUTTER BLOCK: 1 blk x 10000g (UPP) = 10000g total
--   This means 1 blk = 10000g for THIS product only.
-- Generic unit conversions (kg to g) live in units_of_measure.base_unit_multiplier.
-- Product-specific conversions (1 blk of BUTTER = 10000g) live here.
```

## 4. Product & Ingredient Tables

These tables model the 657-product, 31-column Product List from the Excel workbook.

### 4.1 products

The central ingredient table. Each row represents a purchasable ingredient or material. This is the most critical table in the system -- it is the source of truth for cost calculations.

```sql
CREATE TABLE products (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,

  -- ==========================================================================
  -- Identity (Excel columns: Product name, Brand)
  -- ==========================================================================
  name            TEXT NOT NULL,                       -- Excel: "Product name". e.g., "BUTTER BLOCK"
  brand           TEXT,                                -- Excel: "Brand". e.g., "ANCHOR"
  sku             TEXT,                                -- Internal SKU for barcode/POS integration
  barcode         TEXT,                                -- EAN/UPC barcode
  description     TEXT,                                -- Extended description for search
  image_url       TEXT,                                -- Supabase storage path

  -- ==========================================================================
  -- Classification (Excel columns: Category, Status)
  -- ==========================================================================
  status          product_status NOT NULL DEFAULT 'NEW',
  -- Category is handled via the product_categories junction table (M:N)
  -- because a product can belong to multiple categories.

  -- ==========================================================================
  -- Purchase Configuration (Excel columns: PPC, Purchase Unit, UPP, Base Unit, Total)
  -- ==========================================================================
  -- These fields describe HOW the product is purchased and the conversion
  -- from purchase units to working units.

  purchase_unit_id UUID REFERENCES units_of_measure(id),
  -- Excel: "Purchase Unit". The unit in which this product is bought.
  -- e.g., blk (block), kg, ea (each), bch (bunch)

  pieces_per_case  INT NOT NULL DEFAULT 1 CHECK (pieces_per_case > 0),
  -- Excel: "PPC" (Pieces Per Case). How many individual items in one purchase unit.
  -- e.g., BUTTER BLOCK: PPC = 1 (1 block per case)

  units_per_piece_mg BIGINT NOT NULL DEFAULT 1000 CHECK (units_per_piece_mg > 0),
  -- Excel: "UPP" (Units Per Pack) stored as milligrams.
  -- The net weight/volume of ONE piece in base units.
  -- Excel example: BUTTER BLOCK UPP = 10000 (grams) -> stored as 10000000 (mg)
  -- For count items (ea), this represents the unit weight for costing.

  base_unit_id    UUID REFERENCES units_of_measure(id),
  -- Excel: "Base Unit". The smallest unit used in recipes.
  -- Always grams (g) in the Excel workbook, but we allow flexibility.

  -- total_base_units = pieces_per_case * units_per_piece_mg
  -- Excel: "Total" = PPC x UPP. This is a COMPUTED value, not stored.
  -- Calculated in views and functions.

  working_unit_id UUID REFERENCES units_of_measure(id),
  -- Excel: "Working Unit". The unit chefs use when building recipes.
  -- May differ from base unit (e.g., recipe calls for "kg" even though
  -- cost is calculated per gram).

  -- ==========================================================================
  -- Cost (Excel columns: Buying/U, Gross/U, Nett/U)
  -- ==========================================================================
  -- All costs are in MINOR CURRENCY UNITS (fils for AED, cents for USD).
  -- This eliminates floating-point errors in cost calculations.

  buying_cost     BIGINT NOT NULL DEFAULT 0,
  -- Excel: "Buying/U". The total purchase cost for one purchase unit in minor currency.
  -- e.g., BUTTER BLOCK: 1757000 fils = 17.57 AED
  -- Note: The Excel appears to store this in a scaled format. We normalize to fils.

  currency_code   CHAR(3) NOT NULL DEFAULT 'AED' REFERENCES currencies(code),
  -- Currency of the buying_cost. Defaults to org currency.

  -- gross_cost_per_base_unit = buying_cost / total_base_units
  -- Excel: "Gross/U" = Buying / Total. COMPUTED, not stored.

  -- nett_cost_per_base_unit = gross_cost_per_base_unit * ((waste_percent / 100) + 1)
  -- Excel: "Nett/U" = Gross x ((Ref%/100)+1). COMPUTED, not stored.

  -- ==========================================================================
  -- Yield & Waste (Excel columns: Gross weight, Waste amount, Ref%, Yield%)
  -- ==========================================================================

  gross_weight_mg BIGINT,
  -- Excel: "Gross weight". The weight before trimming/preparation, in milligrams.
  -- e.g., BUTTER BLOCK: 1000g = 1000000 mg

  waste_amount_mg BIGINT NOT NULL DEFAULT 0,
  -- Excel: "Waste amount". Weight lost during preparation, in milligrams.
  -- e.g., BUTTER BLOCK: 0g = 0 mg (no waste for butter)

  -- waste_percent = (waste_amount_mg / gross_weight_mg) * 100
  -- Excel: "Ref%" = (Waste / Gross) x 100. COMPUTED, not stored.
  -- Used in the recipe cost formula: Gross Qty = (100 x Nett) / (100 - Ref%)

  -- yield_percent = 100 - waste_percent
  -- Excel: "Yield%" = 100 - Ref%. COMPUTED, not stored.

  -- ==========================================================================
  -- Storage & Handling
  -- ==========================================================================
  storage_temp_min_c  NUMERIC(5, 2),                   -- Min storage temperature in Celsius
  storage_temp_max_c  NUMERIC(5, 2),                   -- Max storage temperature
  shelf_life_days     INT,                             -- Days from receipt to expiry
  is_perishable       BOOLEAN NOT NULL DEFAULT false,

  -- ==========================================================================
  -- Flags
  -- ==========================================================================
  is_sub_recipe_output BOOLEAN NOT NULL DEFAULT false,
  -- True when this product row represents the output of a sub-recipe.
  -- Excel: Sub recipes feed back into the Product List as ingredients.
  -- The sub_recipe_id links to the sub_recipe that produces this product.
  linked_sub_recipe_id UUID,
  -- References the sub_recipe whose output this product represents.
  -- Set when is_sub_recipe_output = true.

  -- ==========================================================================
  -- Audit
  -- ==========================================================================
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),
  updated_by      UUID REFERENCES auth.users(id),
  deleted_at      TIMESTAMPTZ,

  -- Constraints
  UNIQUE (organization_id, name, COALESCE(brand, '')),
  CHECK (waste_amount_mg >= 0),
  CHECK (buying_cost >= 0),
  CHECK (gross_weight_mg IS NULL OR gross_weight_mg > 0)
);

-- WHY: This table is the heart of the system. It replaces the Excel Product List
-- (Table7, 657 rows, 31 columns). Every column maps to a specific Excel field
-- or to a requirement derived from the Excel formulas.
--
-- DESIGN DECISIONS:
-- 1. Computed columns (Gross/U, Nett/U, Ref%, Yield%, Total) are NOT stored.
--    They are calculated in views and functions to avoid update anomalies.
--    If a product's buying_cost changes, all derived values update automatically.
--
-- 2. Costs are in minor currency units (BIGINT) to avoid floating-point errors.
--    The Excel workbook stores costs like 1757000 which appears to be fils or
--    a scaled integer. We normalize everything to minor currency units.
--
-- 3. Weights are in milligrams (BIGINT) for the same reason.
--
-- 4. Sub-recipe outputs are modeled as products with is_sub_recipe_output=true.
--    This mirrors the Excel approach where sub-recipe outputs appear in the
--    Product List and can be used as ingredients in other recipes.

COMMENT ON TABLE products IS 'Central ingredient/product table. Maps to the Excel Product List (Table7, 657 products, 31 columns).';
COMMENT ON COLUMN products.pieces_per_case IS 'Excel: PPC (Pieces Per Case). Number of items per purchase unit.';
COMMENT ON COLUMN products.units_per_piece_mg IS 'Excel: UPP (Units Per Pack) in milligrams. Weight of one piece.';
COMMENT ON COLUMN products.buying_cost IS 'Excel: Buying/U. Total purchase cost in minor currency units (fils/cents).';
COMMENT ON COLUMN products.waste_amount_mg IS 'Excel: Waste amount in milligrams. Used to calculate Ref% and Yield%.';
```

### 4.3 nutrition_profiles

Nutritional information per 100g of product. Maps to the 9 nutrition columns in the Excel Product List.

```sql
CREATE TABLE nutrition_profiles (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,

  -- Polymorphic reference: can belong to a product, recipe version, or sub-recipe version
  product_id              UUID REFERENCES products(id) ON DELETE CASCADE,
  recipe_version_id       UUID,  -- FK added after recipe_versions table is created
  sub_recipe_version_id   UUID,  -- FK added after sub_recipe_versions table is created
  -- Exactly one of these three must be non-null (enforced by CHECK)

  -- ==========================================================================
  -- All values are per 100g of the item, stored as integers in milligrams
  -- or micrograms as noted. This matches the Excel convention.
  -- ==========================================================================

  -- Excel: "Fat" per 100g (stored as mg per 100g for precision)
  fat_mg          INT,             -- e.g., BUTTER: 82g = 82000 mg per 100g
  -- Excel: "Carbs" per 100g
  carbs_mg        INT,             -- e.g., BUTTER: 0.7g = 700 mg per 100g
  -- Excel: "Protein" per 100g
  protein_mg      INT,             -- e.g., BUTTER: 0.6g = 600 mg per 100g

  -- Excel: "Vit A" per 100g (stored as mcg RAE)
  vitamin_a_mcg   INT,
  -- Excel: "Vit C" per 100g (stored as mg)
  vitamin_c_mg    INT,
  -- Excel: "Calcium" per 100g (stored as mg)
  calcium_mg      INT,
  -- Excel: "Iron" per 100g (stored as mg, scaled x100 for precision)
  iron_mg_x100    INT,             -- 2.5mg stored as 250
  -- Excel: "Sodium" per 100g (stored as mg)
  sodium_mg       INT,

  -- Excel: "K.Cal" = (Fat x 9) + (Carbs x 4) + (Protein x 4)
  -- COMPUTED value, but we store it for query performance since it's
  -- used in every recipe nutrition rollup.
  kcal_per_100g   INT,             -- Stored as integer kcal

  -- Extended nutrition (not in Excel but needed for compliance)
  fiber_mg        INT,
  sugar_mg        INT,
  saturated_fat_mg INT,
  trans_fat_mg    INT,
  cholesterol_mg  INT,
  potassium_mg    INT,

  -- Dietary flags
  is_organic      BOOLEAN DEFAULT false,
  is_halal        BOOLEAN DEFAULT true,                -- Default true for UAE market
  is_kosher       BOOLEAN,
  is_vegan        BOOLEAN,
  is_vegetarian   BOOLEAN,
  is_gluten_free  BOOLEAN,

  -- Source of nutrition data
  data_source     TEXT,                                -- "manufacturer", "usda", "manual", "ai_estimated"
  verified_at     TIMESTAMPTZ,
  verified_by     UUID REFERENCES auth.users(id),

  -- Audit
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),
  updated_by      UUID REFERENCES auth.users(id),

  -- Exactly one parent must be set
  CHECK (
    (product_id IS NOT NULL)::int +
    (recipe_version_id IS NOT NULL)::int +
    (sub_recipe_version_id IS NOT NULL)::int = 1
  )
);

-- WHY: The Excel Product List has 9 nutrition columns per product (Fat, Carbs,
-- Protein, Vit A, Vit C, Calcium, Iron, Sodium, K.Cal). The Recipe Template
-- rolls these up into "Nutrition per portion with RDA comparisons".
-- This table stores nutrition at three levels:
--   1. Product: raw ingredient nutrition per 100g (from Excel)
--   2. Recipe version: computed nutrition per portion (rolled up from ingredients)
--   3. Sub-recipe version: computed nutrition per 100g of output
-- The polymorphic design avoids three separate nutrition tables with identical columns.

COMMENT ON TABLE nutrition_profiles IS 'Nutrition per 100g. Maps to Excel columns: Fat, Carbs, Protein, Vit A, Vit C, Calcium, Iron, Sodium, K.Cal.';
COMMENT ON COLUMN nutrition_profiles.kcal_per_100g IS 'Excel: K.Cal = (Fat x 9) + (Carbs x 4) + (Protein x 4). Stored for query performance.';
```

### 5.2 recipe_versions

Each version captures a complete snapshot of recipe ingredients, yield, and pricing at a point in time.

```sql
CREATE TABLE recipe_versions (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  recipe_id       UUID NOT NULL REFERENCES recipes(id) ON DELETE CASCADE,

  version_number  INT NOT NULL,                        -- 1, 2, 3, ...
  is_current      BOOLEAN NOT NULL DEFAULT true,       -- Only one version is current

  -- ==========================================================================
  -- Yield & Portioning (Excel: Yield field in Recipe Template)
  -- ==========================================================================
  yield_quantity  NUMERIC(10, 3) NOT NULL DEFAULT 1,   -- Number of portions/servings
  yield_unit_id   UUID REFERENCES units_of_measure(id), -- "portion", "serving", "kg"
  yield_weight_mg BIGINT,                              -- Total recipe output weight in mg

  -- ==========================================================================
  -- Pricing (Excel: Price W/VAT, Price-VAT, Total+5%)
  -- ==========================================================================
  selling_price_minor BIGINT,                          -- Menu price in minor currency units (fils/cents)
  -- Excel: "Price W/VAT" (price with VAT)
  selling_price_ex_tax_minor BIGINT,                   -- Price excluding tax
  -- Excel: "Price-VAT"
  tax_rate_id     UUID REFERENCES tax_rates(id),       -- Which tax rate applies

  -- ==========================================================================
  -- Calculated Cost Summary (denormalized for query performance)
  -- Updated by trigger when ingredients change
  -- ==========================================================================
  total_cost_minor BIGINT,                             -- Sum of all ingredient line costs
  -- Excel: "Total Cost" = SUMIF of ingredient line costs
  cost_with_overhead_minor BIGINT,                     -- Total cost + overhead percentage
  -- Excel: "Total+5%" = Total Cost * 1.05
  cost_per_portion_minor BIGINT,                       -- total_cost / yield_quantity
  food_cost_percent NUMERIC(6, 3),                     -- (total_cost / selling_price_ex_tax) * 100
  -- Excel: "Food Cost%"
  contribution_margin_minor BIGINT,                    -- selling_price_ex_tax - cost_per_portion
  -- Excel: "Contribution Margin"

  -- ==========================================================================
  -- Preparation
  -- ==========================================================================
  prep_time_minutes   INT,
  cook_time_minutes   INT,
  rest_time_minutes   INT,
  total_time_minutes  INT,                             -- Computed or manual
  difficulty_level    SMALLINT CHECK (difficulty_level BETWEEN 1 AND 5),
  instructions        JSONB,                           -- Ordered steps as JSON array
  chef_notes          TEXT,

  -- ==========================================================================
  -- Change Tracking
  -- ==========================================================================
  change_reason   TEXT,                                -- Why this version was created
  approved_by     UUID REFERENCES auth.users(id),
  approved_at     TIMESTAMPTZ,

  -- Audit
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),
  updated_by      UUID REFERENCES auth.users(id),

  UNIQUE (recipe_id, version_number)
);

-- WHY: The Excel workbook has no versioning -- edits overwrite previous values.
-- This is a critical gap: when the chef changes a recipe, the old cost data is
-- lost. recipe_versions provides full history. The cost summary fields are
-- denormalized (duplicated from calculations) for query performance: dashboards
-- that show "food cost % across all recipes" should not require joining and
-- summing all ingredient lines for every recipe.

COMMENT ON TABLE recipe_versions IS 'Versioned recipe snapshots. Each version captures ingredients, costs, and yield at a point in time.';
COMMENT ON COLUMN recipe_versions.total_cost_minor IS 'Excel: Total Cost (SUMIF). Denormalized sum of ingredient line costs.';
```

### 5.3 recipe_ingredients

Individual ingredient lines within a recipe version. Maps to the 26 ingredient slots in the Excel Recipe Template.

```sql
CREATE TABLE recipe_ingredients (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id     UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  recipe_version_id   UUID NOT NULL REFERENCES recipe_versions(id) ON DELETE CASCADE,

  -- ==========================================================================
  -- What ingredient is this?
  -- ==========================================================================
  ingredient_type     ingredient_ref_type NOT NULL DEFAULT 'PRODUCT',
  product_id          UUID REFERENCES products(id),    -- Set when ingredient_type = 'PRODUCT'
  sub_recipe_id       UUID REFERENCES recipes(id),     -- Set when ingredient_type = 'SUB_RECIPE'
  -- Exactly one must be set based on ingredient_type

  -- ==========================================================================
  -- Quantity (Excel: Name lookup -> auto Unit, Nett Qty, Gross Qty)
  -- ==========================================================================
  sort_order      INT NOT NULL DEFAULT 0,              -- Display sequence (1-26 in Excel)

  nett_quantity_mg BIGINT NOT NULL,
  -- Excel: The quantity the chef actually needs (Nett Qty), in milligrams.
  -- e.g., 200g of butter = 200000 mg

  unit_id         UUID REFERENCES units_of_measure(id),
  -- Excel: auto-populated "Unit" column. The unit the chef specified.
  -- Stored for display purposes; calculations use milligrams.

  -- gross_quantity_mg = (100 * nett_quantity_mg) / (100 - waste_percent)
  -- Excel: "Gross Qty" = (100 x Nett) / (100 - Ref%)
  -- COMPUTED, not stored. Uses the product's current waste percentage.
  -- This is the amount to actually requisition, accounting for trim/waste.

  -- ==========================================================================
  -- Cost (Excel: Cost/U, Line Cost)
  -- ==========================================================================
  -- cost_per_unit = product.nett_cost_per_base_unit (at time of version creation)
  -- line_cost = gross_quantity_mg * cost_per_unit
  -- Excel: "Line Cost" for each ingredient row

  -- We store a snapshot of the cost at version creation time for immutability
  cost_per_base_unit_minor BIGINT,
  -- The nett cost per base unit at the time this version was created.
  -- Prevents historical recipe costs from changing when product prices update.

  line_cost_minor BIGINT,
  -- Computed: gross_quantity * cost_per_base_unit. Stored for performance.

  -- ==========================================================================
  -- Notes
  -- ==========================================================================
  preparation_note TEXT,                               -- "diced", "julienned", "room temperature"
  is_optional      BOOLEAN NOT NULL DEFAULT false,     -- Optional garnish/add-on

  -- Audit
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_by      UUID REFERENCES auth.users(id),
  updated_by      UUID REFERENCES auth.users(id),

  CHECK (
    (ingredient_type = 'PRODUCT' AND product_id IS NOT NULL AND sub_recipe_id IS NULL) OR
    (ingredient_type = 'SUB_RECIPE' AND sub_recipe_id IS NOT NULL AND product_id IS NULL)
  )
);

-- WHY: Each row maps to one of the 26 ingredient slots in the Excel Recipe Template.
-- The Excel template has columns: Name (lookup key) -> auto Unit, Ref%, Gross Qty,
-- Cost/U, Line Cost. This table captures all of those.
--
-- KEY DESIGN DECISION: We store cost_per_base_unit_minor and line_cost_minor as
-- snapshots at version creation time. This means when a product price changes,
-- existing recipe versions retain their historical costs. Only NEW versions
-- pick up the new price. This is essential for accurate historical cost analysis.
--
-- The ingredient can reference either a raw product or a sub-recipe (which is
-- itself a recipe of type SUB_RECIPE). This enables the Excel hierarchy:
-- Products -> Sub Recipes -> Recipes

COMMENT ON TABLE recipe_ingredients IS 'Ingredient lines within a recipe version. Maps to the 26 ingredient slots in the Excel Recipe Template.';
COMMENT ON COLUMN recipe_ingredients.nett_quantity_mg IS 'Excel: Nett Qty. The amount the chef needs, in milligrams.';
COMMENT ON COLUMN recipe_ingredients.cost_per_base_unit_minor IS 'Snapshot of product nett cost/unit at version creation. Prevents historical costs from drifting.';
COMMENT ON COLUMN recipe_ingredients.line_cost_minor IS 'Excel: Line Cost. gross_quantity * cost_per_unit. Stored for performance.';
```

### 15.5 Cascade Rules Rationale

- **CASCADE**: Used when the child has no meaning without the parent. Deleting an organization deletes all its data. Deleting a recipe deletes its versions and ingredients.
- **SET NULL**: Used for optional references. If a user is deleted, their audit references become NULL rather than cascading to delete the audited records.
- **RESTRICT** (implicit): Foreign keys without ON DELETE default to RESTRICT, preventing deletion of referenced entities. Products cannot be deleted if they appear in recipe ingredients.

## 17. Row Level Security Policies

All RLS policies follow the same pattern: users can only access data belonging to their organization. The `get_user_org_id()` function extracts the organization from the JWT claims.

### 17.1 Helper Functions

```sql
-- Extract the current user's organization ID from JWT claims
CREATE OR REPLACE FUNCTION get_user_org_id()
RETURNS UUID
LANGUAGE sql
STABLE
SECURITY DEFINER
AS $$
  SELECT (auth.jwt() -> 'app_metadata' ->> 'organization_id')::uuid;
$$;

-- Check if the current user has a specific permission
CREATE OR REPLACE FUNCTION user_has_permission(p_resource TEXT, p_action TEXT)
RETURNS BOOLEAN
LANGUAGE sql
STABLE
SECURITY DEFINER
AS $$
  SELECT EXISTS (
    SELECT 1
    FROM user_roles ur
    JOIN role_permissions rp ON rp.role_id = ur.role_id
    JOIN permissions p ON p.id = rp.permission_id
    WHERE ur.user_id = auth.uid()
      AND ur.organization_id = get_user_org_id()
      AND p.resource = p_resource
      AND p.action = p_action
  );
$$;

-- Check if user is an org admin
CREATE OR REPLACE FUNCTION is_org_admin()
RETURNS BOOLEAN
LANGUAGE sql
STABLE
SECURITY DEFINER
AS $$
  SELECT EXISTS (
    SELECT 1 FROM users
    WHERE id = auth.uid()
      AND organization_id = get_user_org_id()
      AND is_org_admin = true
  );
$$;
```

## 18. Database Functions

### 18.1 Cost Calculation Functions

```sql
-- =============================================================================
-- Calculate total base units for a product
-- Excel: Total = PPC x UPP
-- =============================================================================
CREATE OR REPLACE FUNCTION calc_product_total_base_units(p_product_id UUID)
RETURNS BIGINT
LANGUAGE sql
STABLE
AS $$
  SELECT pieces_per_case::bigint * units_per_piece_mg
  FROM products
  WHERE id = p_product_id;
$$;

COMMENT ON FUNCTION calc_product_total_base_units IS 'Excel: Total = PPC x UPP. Returns total weight in mg.';

-- =============================================================================
-- Calculate gross cost per base unit
-- Excel: Gross/U = Buying / Total
-- Returns cost in minor currency per milligram (scaled by 1,000,000 for precision)
-- =============================================================================
CREATE OR REPLACE FUNCTION calc_gross_cost_per_mg(p_product_id UUID)
RETURNS NUMERIC
LANGUAGE sql
STABLE
AS $$
  SELECT
    CASE
      WHEN (pieces_per_case::bigint * units_per_piece_mg) > 0
      THEN buying_cost::numeric * 1000000 / (pieces_per_case::bigint * units_per_piece_mg)::numeric
      ELSE 0
    END
  FROM products
  WHERE id = p_product_id;
$$;

COMMENT ON FUNCTION calc_gross_cost_per_mg IS 'Excel: Gross/U = Buying/Total. Cost per mg scaled by 1M for precision.';

-- =============================================================================
-- Calculate waste percentage
-- Excel: Ref% = (Waste / Gross) x 100
-- =============================================================================
CREATE OR REPLACE FUNCTION calc_waste_percent(p_product_id UUID)
RETURNS NUMERIC
LANGUAGE sql
STABLE
AS $$
  SELECT
    CASE
      WHEN gross_weight_mg IS NOT NULL AND gross_weight_mg > 0
      THEN (waste_amount_mg::numeric / gross_weight_mg::numeric) * 100
      ELSE 0
    END
  FROM products
  WHERE id = p_product_id;
$$;

COMMENT ON FUNCTION calc_waste_percent IS 'Excel: Ref% = (Waste / Gross) x 100.';

-- =============================================================================
-- Calculate nett cost per base unit (accounting for waste)
-- Excel: Nett/U = Gross x ((Ref%/100) + 1)
-- =============================================================================
CREATE OR REPLACE FUNCTION calc_nett_cost_per_mg(p_product_id UUID)
RETURNS NUMERIC
LANGUAGE sql
STABLE
AS $$
  SELECT calc_gross_cost_per_mg(p_product_id) * ((calc_waste_percent(p_product_id) / 100) + 1);
$$;

COMMENT ON FUNCTION calc_nett_cost_per_mg IS 'Excel: Nett/U = Gross x ((Ref%/100)+1). Waste-adjusted cost per mg.';

-- =============================================================================
-- Calculate gross quantity from nett quantity (accounting for waste)
-- Excel: Gross Qty = (100 x Nett) / (100 - Ref%)
-- =============================================================================
CREATE OR REPLACE FUNCTION calc_gross_quantity_mg(
  p_nett_quantity_mg BIGINT,
  p_product_id UUID
)
RETURNS BIGINT
LANGUAGE sql
STABLE
AS $$
  SELECT
    CASE
      WHEN (100 - calc_waste_percent(p_product_id)) > 0
      THEN ((100::numeric * p_nett_quantity_mg::numeric) / (100 - calc_waste_percent(p_product_id)))::bigint
      ELSE p_nett_quantity_mg
    END;
$$;

COMMENT ON FUNCTION calc_gross_quantity_mg IS 'Excel: Gross Qty = (100 x Nett) / (100 - Ref%). Accounts for waste in requisition.';

-- =============================================================================
-- Calculate recipe version total cost
-- Sums all ingredient line costs for a recipe version
-- Excel: Total Cost = SUMIF of ingredient line costs
-- =============================================================================
CREATE OR REPLACE FUNCTION calc_recipe_version_cost(p_recipe_version_id UUID)
RETURNS TABLE (
  total_cost_minor BIGINT,
  cost_per_portion_minor BIGINT,
  food_cost_percent NUMERIC,
  contribution_margin_minor BIGINT
)
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
  v_total BIGINT;
  v_yield NUMERIC;
  v_selling_price BIGINT;
  v_selling_price_ex_tax BIGINT;
  v_cost_per_portion BIGINT;
  v_food_cost_pct NUMERIC;
  v_contribution BIGINT;
BEGIN
  -- Sum ingredient line costs
  SELECT COALESCE(SUM(ri.line_cost_minor), 0)
  INTO v_total
  FROM recipe_ingredients ri
  WHERE ri.recipe_version_id = p_recipe_version_id;

  -- Get yield and pricing
  SELECT rv.yield_quantity, rv.selling_price_minor, rv.selling_price_ex_tax_minor
  INTO v_yield, v_selling_price, v_selling_price_ex_tax
  FROM recipe_versions rv
  WHERE rv.id = p_recipe_version_id;

  -- Cost per portion
  v_cost_per_portion := CASE
    WHEN v_yield > 0 THEN (v_total::numeric / v_yield)::bigint
    ELSE v_total
  END;

  -- Food cost percentage
  v_food_cost_pct := CASE
    WHEN v_selling_price_ex_tax IS NOT NULL AND v_selling_price_ex_tax > 0
    THEN (v_cost_per_portion::numeric / v_selling_price_ex_tax::numeric) * 100
    ELSE NULL
  END;

  -- Contribution margin
  v_contribution := CASE
    WHEN v_selling_price_ex_tax IS NOT NULL
    THEN v_selling_price_ex_tax - v_cost_per_portion
    ELSE NULL
  END;

  RETURN QUERY SELECT v_total, v_cost_per_portion, v_food_cost_pct, v_contribution;
END;
$$;

COMMENT ON FUNCTION calc_recipe_version_cost IS 'Excel: Total Cost, Cost/Portion, Food Cost%, Contribution Margin. Calculates all recipe cost metrics.';
```

### 18.2 Nutrition Rollup Function

```sql
-- =============================================================================
-- Roll up nutrition from ingredients to recipe version
-- Each ingredient contributes nutrition proportional to its quantity
-- Excel: Nutrition per portion with RDA comparisons
-- =============================================================================
CREATE OR REPLACE FUNCTION calc_recipe_nutrition(p_recipe_version_id UUID)
RETURNS TABLE (
  fat_mg INT,
  carbs_mg INT,
  protein_mg INT,
  vitamin_a_mcg INT,
  vitamin_c_mg INT,
  calcium_mg INT,
  iron_mg_x100 INT,
  sodium_mg INT,
  kcal_per_100g INT,
  kcal_per_portion INT
)
LANGUAGE plpgsql
STABLE
AS $$
DECLARE
  v_yield NUMERIC;
  v_yield_weight_mg BIGINT;
  v_total_weight_mg BIGINT;
  v_fat NUMERIC := 0;
  v_carbs NUMERIC := 0;
  v_protein NUMERIC := 0;
  v_vita NUMERIC := 0;
  v_vitc NUMERIC := 0;
  v_calcium NUMERIC := 0;
  v_iron NUMERIC := 0;
  v_sodium NUMERIC := 0;
  rec RECORD;
BEGIN
  -- Get recipe yield
  SELECT rv.yield_quantity, rv.yield_weight_mg
  INTO v_yield, v_yield_weight_mg
  FROM recipe_versions rv
  WHERE rv.id = p_recipe_version_id;

  -- Sum nutrition from all ingredients, weighted by quantity
  FOR rec IN
    SELECT
      ri.nett_quantity_mg,
      np.fat_mg AS ing_fat,
      np.carbs_mg AS ing_carbs,
      np.protein_mg AS ing_protein,
      np.vitamin_a_mcg AS ing_vita,
      np.vitamin_c_mg AS ing_vitc,
      np.calcium_mg AS ing_calcium,
      np.iron_mg_x100 AS ing_iron,
      np.sodium_mg AS ing_sodium
    FROM recipe_ingredients ri
    JOIN nutrition_profiles np ON np.product_id = ri.product_id
    WHERE ri.recipe_version_id = p_recipe_version_id
      AND ri.ingredient_type = 'PRODUCT'
  LOOP
    -- Nutrition values are per 100g; scale by ingredient quantity
    -- ingredient_qty_mg / 100000 (100g in mg) * nutrition_per_100g
    v_fat     := v_fat     + COALESCE(rec.ing_fat, 0)::numeric     * rec.nett_quantity_mg::numeric / 100000;
    v_carbs   := v_carbs   + COALESCE(rec.ing_carbs, 0)::numeric   * rec.nett_quantity_mg::numeric / 100000;
    v_protein := v_protein + COALESCE(rec.ing_protein, 0)::numeric * rec.nett_quantity_mg::numeric / 100000;
    v_vita    := v_vita    + COALESCE(rec.ing_vita, 0)::numeric    * rec.nett_quantity_mg::numeric / 100000;
    v_vitc    := v_vitc    + COALESCE(rec.ing_vitc, 0)::numeric   * rec.nett_quantity_mg::numeric / 100000;
    v_calcium := v_calcium + COALESCE(rec.ing_calcium, 0)::numeric * rec.nett_quantity_mg::numeric / 100000;
    v_iron    := v_iron    + COALESCE(rec.ing_iron, 0)::numeric    * rec.nett_quantity_mg::numeric / 100000;
    v_sodium  := v_sodium  + COALESCE(rec.ing_sodium, 0)::numeric  * rec.nett_quantity_mg::numeric / 100000;
  END LOOP;

  -- Calculate total weight
  v_total_weight_mg := COALESCE(v_yield_weight_mg,
    (SELECT COALESCE(SUM(nett_quantity_mg), 0)
     FROM recipe_ingredients
     WHERE recipe_version_id = p_recipe_version_id));

  RETURN QUERY SELECT
    -- Per 100g of recipe output
    CASE WHEN v_total_weight_mg > 0
      THEN (v_fat     * 100000 / v_total_weight_mg)::int ELSE 0 END,
    CASE WHEN v_total_weight_mg > 0
      THEN (v_carbs   * 100000 / v_total_weight_mg)::int ELSE 0 END,
    CASE WHEN v_total_weight_mg > 0
      THEN (v_protein * 100000 / v_total_weight_mg)::int ELSE 0 END,
    CASE WHEN v_total_weight_mg > 0
      THEN (v_vita    * 100000 / v_total_weight_mg)::int ELSE 0 END,
    CASE WHEN v_total_weight_mg > 0
      THEN (v_vitc    * 100000 / v_total_weight_mg)::int ELSE 0 END,
    CASE WHEN v_total_weight_mg > 0
      THEN (v_calcium * 100000 / v_total_weight_mg)::int ELSE 0 END,
    CASE WHEN v_total_weight_mg > 0
      THEN (v_iron    * 100000 / v_total_weight_mg)::int ELSE 0 END,
    CASE WHEN v_total_weight_mg > 0
      THEN (v_sodium  * 100000 / v_total_weight_mg)::int ELSE 0 END,
    -- kcal per 100g: (fat*9 + carbs*4 + protein*4) -- fat/carbs/protein are in mg per 100g
    CASE WHEN v_total_weight_mg > 0
      THEN (
        (v_fat * 100000 / v_total_weight_mg)::numeric * 9 / 1000 +
        (v_carbs * 100000 / v_total_weight_mg)::numeric * 4 / 1000 +
        (v_protein * 100000 / v_total_weight_mg)::numeric * 4 / 1000
      )::int
      ELSE 0 END,
    -- kcal per portion
    CASE WHEN v_yield > 0
      THEN (
        (v_fat::numeric * 9 / 1000 + v_carbs::numeric * 4 / 1000 + v_protein::numeric * 4 / 1000) / v_yield
      )::int
      ELSE 0 END;
END;
$$;

COMMENT ON FUNCTION calc_recipe_nutrition IS 'Rolls up ingredient nutrition to recipe level. Maps to Excel "Nutrition per portion with RDA comparisons".';
```

### 18.3 Allergen Inheritance Function

```sql
-- =============================================================================
-- Collect all allergens for a recipe version from its ingredients
-- Allergens propagate: Product -> Sub-Recipe -> Recipe
-- =============================================================================
CREATE OR REPLACE FUNCTION refresh_recipe_allergens(p_recipe_version_id UUID)
RETURNS void
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  v_org_id UUID;
BEGIN
  -- Get organization
  SELECT rv.organization_id INTO v_org_id
  FROM recipe_versions rv
  WHERE rv.id = p_recipe_version_id;

  -- Clear existing allergens for this version
  DELETE FROM recipe_allergens WHERE recipe_version_id = p_recipe_version_id;

  -- Insert allergens from direct product ingredients
  INSERT INTO recipe_allergens (organization_id, recipe_version_id, allergen_id, severity, source_product_ids)
  SELECT
    v_org_id,
    p_recipe_version_id,
    pa.allergen_id,
    MAX(pa.severity),  -- Take the highest severity if multiple products have the same allergen
    array_agg(DISTINCT pa.product_id)
  FROM recipe_ingredients ri
  JOIN product_allergens pa ON pa.product_id = ri.product_id
  WHERE ri.recipe_version_id = p_recipe_version_id
    AND ri.ingredient_type = 'PRODUCT'
  GROUP BY pa.allergen_id;

  -- Insert/merge allergens from sub-recipe ingredients
  -- Sub-recipes propagate their allergens to parent recipes
  INSERT INTO recipe_allergens (organization_id, recipe_version_id, allergen_id, severity, source_sub_recipe_ids)
  SELECT
    v_org_id,
    p_recipe_version_id,
    ra_sub.allergen_id,
    MAX(ra_sub.severity),
    array_agg(DISTINCT ri.sub_recipe_id)
  FROM recipe_ingredients ri
  JOIN recipes sub_r ON sub_r.id = ri.sub_recipe_id
  JOIN recipe_versions sub_rv ON sub_rv.recipe_id = sub_r.id AND sub_rv.is_current = true
  JOIN recipe_allergens ra_sub ON ra_sub.recipe_version_id = sub_rv.id
  WHERE ri.recipe_version_id = p_recipe_version_id
    AND ri.ingredient_type = 'SUB_RECIPE'
    AND NOT EXISTS (
      SELECT 1 FROM recipe_allergens ra_existing
      WHERE ra_existing.recipe_version_id = p_recipe_version_id
        AND ra_existing.allergen_id = ra_sub.allergen_id
    )
  GROUP BY ra_sub.allergen_id
  ON CONFLICT (recipe_version_id, allergen_id) DO UPDATE
  SET
    severity = GREATEST(recipe_allergens.severity, EXCLUDED.severity),
    source_sub_recipe_ids = recipe_allergens.source_sub_recipe_ids || EXCLUDED.source_sub_recipe_ids;
END;
$$;

COMMENT ON FUNCTION refresh_recipe_allergens IS 'Propagates allergens from products and sub-recipes to recipe versions.';
```

### 18.4 Recipe Version Creation Function

```sql
-- =============================================================================
-- Create a new version of a recipe, copying ingredients from the current version
-- =============================================================================
CREATE OR REPLACE FUNCTION create_recipe_version(
  p_recipe_id UUID,
  p_change_reason TEXT DEFAULT NULL,
  p_user_id UUID DEFAULT auth.uid()
)
RETURNS UUID
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  v_new_version_id UUID;
  v_new_version_number INT;
  v_current_version_id UUID;
BEGIN
  -- Get current version number and increment
  SELECT current_version + 1, rv.id
  INTO v_new_version_number, v_current_version_id
  FROM recipes r
  JOIN recipe_versions rv ON rv.recipe_id = r.id AND rv.is_current = true
  WHERE r.id = p_recipe_id;

  -- Mark current version as not current
  UPDATE recipe_versions
  SET is_current = false, updated_at = now()
  WHERE recipe_id = p_recipe_id AND is_current = true;

  -- Create new version by copying current
  INSERT INTO recipe_versions (
    organization_id, recipe_id, version_number, is_current,
    yield_quantity, yield_unit_id, yield_weight_mg,
    selling_price_minor, selling_price_ex_tax_minor, tax_rate_id,
    prep_time_minutes, cook_time_minutes, rest_time_minutes, total_time_minutes,
    difficulty_level, instructions, chef_notes,
    change_reason, created_by
  )
  SELECT
    organization_id, recipe_id, v_new_version_number, true,
    yield_quantity, yield_unit_id, yield_weight_mg,
    selling_price_minor, selling_price_ex_tax_minor, tax_rate_id,
    prep_time_minutes, cook_time_minutes, rest_time_minutes, total_time_minutes,
    difficulty_level, instructions, chef_notes,
    p_change_reason, p_user_id
  FROM recipe_versions
  WHERE id = v_current_version_id
  RETURNING id INTO v_new_version_id;

  -- Copy ingredients to new version with updated costs
  INSERT INTO recipe_ingredients (
    organization_id, recipe_version_id, ingredient_type, product_id, sub_recipe_id,
    sort_order, nett_quantity_mg, unit_id,
    cost_per_base_unit_minor, line_cost_minor,
    preparation_note, is_optional, created_by
  )
  SELECT
    organization_id, v_new_version_id, ingredient_type, product_id, sub_recipe_id,
    sort_order, nett_quantity_mg, unit_id,
    -- Recalculate cost with current product prices
    CASE WHEN ingredient_type = 'PRODUCT'
      THEN calc_nett_cost_per_mg(product_id)::bigint
      ELSE cost_per_base_unit_minor
    END,
    CASE WHEN ingredient_type = 'PRODUCT'
      THEN (calc_gross_quantity_mg(nett_quantity_mg, product_id) *
            calc_nett_cost_per_mg(product_id) / 1000000)::bigint
      ELSE line_cost_minor
    END,
    preparation_note, is_optional, p_user_id
  FROM recipe_ingredients
  WHERE recipe_version_id = v_current_version_id;

  -- Update recipe header
  UPDATE recipes
  SET current_version = v_new_version_number, updated_at = now(), updated_by = p_user_id
  WHERE id = p_recipe_id;

  -- Refresh allergens for new version
  PERFORM refresh_recipe_allergens(v_new_version_id);

  RETURN v_new_version_id;
END;
$$;

COMMENT ON FUNCTION create_recipe_version IS 'Creates a new recipe version, copying ingredients from current and recalculating costs.';
```

```sql
-- =============================================================================
-- Generic audit log trigger function
-- Logs INSERT, UPDATE, DELETE operations to audit_logs
-- =============================================================================
CREATE OR REPLACE FUNCTION trigger_audit_log()
RETURNS TRIGGER
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  v_old_data JSONB;
  v_new_data JSONB;
  v_changed_fields TEXT[];
  v_org_id UUID;
  v_record_id UUID;
  k TEXT;
BEGIN
  -- Extract organization_id and record id
  IF TG_OP = 'DELETE' THEN
    v_old_data := to_jsonb(OLD);
    v_org_id := (v_old_data ->> 'organization_id')::uuid;
    v_record_id := (v_old_data ->> 'id')::uuid;
  ELSE
    v_new_data := to_jsonb(NEW);
    v_org_id := (v_new_data ->> 'organization_id')::uuid;
    v_record_id := (v_new_data ->> 'id')::uuid;
  END IF;

  IF TG_OP = 'UPDATE' THEN
    v_old_data := to_jsonb(OLD);
    v_changed_fields := ARRAY[]::TEXT[];
    FOR k IN SELECT jsonb_object_keys(v_new_data)
    LOOP
      IF v_new_data -> k IS DISTINCT FROM v_old_data -> k THEN
        v_changed_fields := v_changed_fields || k;
      END IF;
    END LOOP;
    -- Skip audit if only updated_at changed (noise reduction)
    IF v_changed_fields = ARRAY['updated_at'] THEN
      RETURN COALESCE(NEW, OLD);
    END IF;
  END IF;

  INSERT INTO audit_logs (
    organization_id, table_name, record_id, action,
    old_data, new_data, changed_fields, user_id
  ) VALUES (
    v_org_id, TG_TABLE_NAME, v_record_id, TG_OP,
    v_old_data, v_new_data, v_changed_fields, auth.uid()
  );

  RETURN COALESCE(NEW, OLD);
END;
$$;
```

```sql
-- =============================================================================
-- When an inventory transaction is inserted, update the inventory item balance
-- =============================================================================
CREATE OR REPLACE FUNCTION trigger_update_inventory_balance()
RETURNS TRIGGER
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
BEGIN
  -- Upsert inventory item
  INSERT INTO inventory_items (
    organization_id, location_id, department_id, product_id,
    quantity_on_hand_mg, unit_id, last_received_at
  ) VALUES (
    NEW.organization_id, NEW.location_id, NEW.department_id, NEW.product_id,
    NEW.quantity_mg, NEW.unit_id,
    CASE WHEN NEW.transaction_type = 'PURCHASE_RECEIPT' THEN now() ELSE NULL END
  )
  ON CONFLICT (location_id, product_id,
    COALESCE(department_id, '00000000-0000-0000-0000-000000000000'::uuid))
  DO UPDATE SET
    quantity_on_hand_mg = inventory_items.quantity_on_hand_mg + NEW.quantity_mg,
    last_received_at = CASE
      WHEN NEW.transaction_type = 'PURCHASE_RECEIPT' THEN now()
      ELSE inventory_items.last_received_at
    END,
    last_cost_minor = CASE
      WHEN NEW.unit_cost_minor IS NOT NULL THEN NEW.unit_cost_minor
      ELSE inventory_items.last_cost_minor
    END,
    updated_at = now();

  RETURN NEW;
END;
$$;

CREATE TRIGGER update_inventory_balance
  AFTER INSERT ON inventory_transactions
  FOR EACH ROW
  EXECUTE FUNCTION trigger_update_inventory_balance();
```

### 19.7 Supplier Price History Trigger

```sql
-- =============================================================================
-- When a supplier product price changes, log to price history
-- =============================================================================
CREATE OR REPLACE FUNCTION trigger_supplier_price_change()
RETURNS TRIGGER
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
BEGIN
  IF OLD.unit_cost_minor IS DISTINCT FROM NEW.unit_cost_minor THEN
    -- Close the previous price period
    UPDATE supplier_price_history
    SET end_date = CURRENT_DATE - 1
    WHERE supplier_product_id = NEW.id
      AND end_date IS NULL;

    -- Insert new price record
    INSERT INTO supplier_price_history (
      organization_id, supplier_product_id, unit_cost_minor,
      currency_code, effective_date,
      change_percent, source, created_by
    ) VALUES (
      NEW.organization_id, NEW.id, NEW.unit_cost_minor,
      NEW.currency_code, CURRENT_DATE,
      CASE WHEN OLD.unit_cost_minor > 0
        THEN ((NEW.unit_cost_minor - OLD.unit_cost_minor)::numeric / OLD.unit_cost_minor::numeric) * 100
        ELSE NULL
      END,
      'price_update',
      NEW.updated_by
    );
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER supplier_price_change
  AFTER UPDATE OF unit_cost_minor ON supplier_products
  FOR EACH ROW
  EXECUTE FUNCTION trigger_supplier_price_change();
```

### 20.1 Product Cost View

Mirrors the Excel Product List calculated columns.

```sql
CREATE OR REPLACE VIEW v_product_costs AS
SELECT
  p.id,
  p.organization_id,
  p.name,
  p.brand,
  p.status,
  p.buying_cost,
  p.currency_code,
  p.pieces_per_case,
  p.units_per_piece_mg,

  -- Excel: Total = PPC x UPP
  (p.pieces_per_case::bigint * p.units_per_piece_mg) AS total_base_units_mg,

  -- Excel: Gross/U = Buying / Total
  CASE
    WHEN (p.pieces_per_case::bigint * p.units_per_piece_mg) > 0
    THEN p.buying_cost::numeric / (p.pieces_per_case::bigint * p.units_per_piece_mg)::numeric
    ELSE 0
  END AS gross_cost_per_mg,

  -- Excel: Ref% = (Waste / Gross) x 100
  CASE
    WHEN p.gross_weight_mg IS NOT NULL AND p.gross_weight_mg > 0
    THEN (p.waste_amount_mg::numeric / p.gross_weight_mg::numeric) * 100
    ELSE 0
  END AS waste_percent,

  -- Excel: Yield% = 100 - Ref%
  CASE
    WHEN p.gross_weight_mg IS NOT NULL AND p.gross_weight_mg > 0
    THEN 100 - (p.waste_amount_mg::numeric / p.gross_weight_mg::numeric) * 100
    ELSE 100
  END AS yield_percent,

  -- Excel: Nett/U = Gross x ((Ref%/100) + 1)
  CASE
    WHEN (p.pieces_per_case::bigint * p.units_per_piece_mg) > 0
    THEN (p.buying_cost::numeric / (p.pieces_per_case::bigint * p.units_per_piece_mg)::numeric)
         * (CASE
              WHEN p.gross_weight_mg IS NOT NULL AND p.gross_weight_mg > 0
              THEN ((p.waste_amount_mg::numeric / p.gross_weight_mg::numeric)) + 1
              ELSE 1
            END)
    ELSE 0
  END AS nett_cost_per_mg,

  p.gross_weight_mg,
  p.waste_amount_mg,
  p.created_at,
  p.updated_at
FROM products p
WHERE p.deleted_at IS NULL;

COMMENT ON VIEW v_product_costs IS 'Calculated product costs mirroring Excel columns: Total, Gross/U, Nett/U, Ref%, Yield%.';
```

## 21. Migration Strategy

### 21.1 Excel Workbook Import Plan

The migration from the two Excel workbooks (Product List and Recipe Templates) follows a phased approach. Each phase is idempotent and can be re-run safely.

#### Phase 1: Reference Data Setup

1. Create the organization record.
2. Create the default location.
3. Seed categories from the 12 Excel categories: BITES, SALADS, COLD, HOT, MAINS, GRILL, SIDES, BREAD, PIZZA, DESSERT, KIDS MENU, HAPPY HOUR.
4. Seed units of measure from the Excel Purchase Unit and Base Unit values: blk, kg, g, ea, bch, pkt, L, ml, etc.
5. Seed the default 5% UAE VAT tax rate.
6. Seed the AED currency.

#### Phase 2: Supplier Import

1. Extract unique supplier names from the Product List "Supplier" column.
2. Create a `suppliers` row for each unique supplier.
3. Map supplier names for deduplication (handle variations like "ANCHOR" vs "Anchor Trading LLC").

#### Phase 3: Product Import (657 products)

Column mapping from Excel to database:

| Excel Column | Database Column | Transform |
|---|---|---|
| Product name | products.name | Trim whitespace, title case |
| Brand | products.brand | Trim whitespace |
| Category | product_categories (junction) | Map to categories.id |
| Supplier | supplier_products (junction) | Map to suppliers.id |
| PPC | products.pieces_per_case | Direct integer |
| Purchase Unit | products.purchase_unit_id | Map to units_of_measure.id |
| UPP | products.units_per_piece_mg | Multiply by 1000 if Excel unit is grams |
| Base Unit | products.base_unit_id | Map to units_of_measure.id |

4. Create `supplier_products` junction rows linking each product to its supplier.
5. Create `unit_conversions` for product-specific conversions (blk -> g based on UPP).

#### Phase 4: Sub-Recipe Import

1. Parse each sub-recipe template from the workbook.
2. Create a `recipes` row with `recipe_type = 'SUB_RECIPE'`.
3. Create the initial `recipe_versions` row (version 1).
4. For each ingredient line (up to 26):
   a. Match the ingredient name to an existing product (fuzzy match).
   b. Create a `recipe_ingredients` row with the quantity and cost snapshot.
5. Create a `products` row for the sub-recipe output with `is_sub_recipe_output = true`.
6. Link: `recipes.output_product_id = new_product.id` and `products.linked_sub_recipe_id = recipes.id`.
7. Calculate the sub-recipe cost: `Total Cost + 5% -> Cost Per Unit = Total / BatchWeight`.

#### Phase 5: Recipe Import

1. Parse each recipe template from the workbook.
2. Create a `recipes` row with `recipe_type = 'STANDARD'`.
3. Create the initial `recipe_versions` row with yield, pricing, and time data.
4. For each ingredient line:
   a. Match to product or sub-recipe output.
   b. Create `recipe_ingredients` with quantity, cost snapshot.
5. The trigger automatically:
   a. Calculates total_cost, food_cost_percent, contribution_margin.
   b. Propagates allergens (once allergens are set on products).
   c. Logs to cost_history.

#### Phase 6: Validation

1. Compare every computed value (Gross/U, Nett/U, Ref%, Yield%, Total Cost, Food Cost%) between the database calculation and the Excel formula result.
2. Flag discrepancies greater than 0.01% for manual review.
3. Generate a validation report showing matched vs. mismatched values.

### 21.2 AI Import Workflow

For ongoing imports after initial migration:

1. User uploads an Excel file or supplier price list.
2. System creates an `ai_imports` row with status `PENDING`.
3. AI parser reads the file, identifies columns, and maps each row to either:
   a. An existing product (update price/details), or
   b. A new product to create.
4. Each row becomes an `ai_import_items` row with the AI's mapping and confidence.
5. User reviews the mapping in a side-by-side UI.
6. User approves, rejects, or overrides each mapping.
7. Approved items are imported into the database.
8. The import status changes to `COMPLETED`.

### 22.1 Critical integrity rules

1. A `product_lot` is created at goods receipt, carries supplier lot/expiry/source receipt data, and is consumed through `lot_movements`; it must never be silently replaced by a current product balance.
2. A supplier invoice can be posted only after permitted two-way or three-way matching. Exceptions require assigned owner, reason, approval and audit event.
3. Time entries are immutable after payroll/accounting export; corrections use adjustment records.
4. A recall case snapshots affected lots, recipe/menu exposure and location actions at launch, while retaining live progress separately.
5. Every external record uses an `external_id_mappings` row and idempotency key; no connector may create duplicate goods receipts, invoices or payments.

## 23. Platform Core and Workspace Boundary Extension

### 23.1 Shared foundation tables

Add `legal_entities`, `business_units`, `regions`, `teams`, `stations`, `cost_centers`, `profit_centers`, `data_classifications`, `access_grants`, `delegations`, `approval_policies`, `approval_policy_rules`, `approval_instances`, `approval_steps`, `approval_decisions`, `segregation_of_duty_rules`, `integration_connections`, `integration_sync_runs`, `external_id_mappings` and `workflow_tasks`. Existing role tables become capability bundles; access is resolved with scope and attributes, not role name alone.

### 23.2 Identity and privacy boundaries

- Keep `auth.users`/application `users`, `employees`, and `supplier_portal_users` separate and link only through controlled identity relations.
- Place compensation, bank/tax, disciplinary, candidate, medical/accommodation and biometric-provider references in restricted HR tables with field-classification metadata, explicit purpose and audited read/export events.
- Store biometric provider references and verification outcome only; do not persist raw templates.
- Store payment-provider/accounting references and status only unless a separate ADR, compliance review and regulated provider scope authorise more.

### 23.3 Workflow integrity

Each approval instance records policy version, subject type/ID, resolved scope, amount/currency where applicable, decision order, delegation, escalation, actor, reason and correlation ID. Database constraints and server functions must reject self-approval and configured SOD conflicts; UI checks are supplementary only.
